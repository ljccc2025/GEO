# GEO 作战平台

面向**工业设计出口业务**的 GEO（Generative Engine Optimization，生成式引擎优化）系统。

目标：当海外买手向 AI 提问「推荐中国优秀的耳塞设计工厂」这类问题时，AI 的答案中出现并推荐本公司。

打法：**真实内容 × 广泛分发**。不做内容农场。

## 项目拆分

原始需求包含三个互不重叠的能力，拆为三个子项目、分三步做：

| # | 子项目 | 说明 | 状态 |
|---|---|---|---|
| 1 | **GEO 作战平台** | 内容生产 + 质检 + 分发 + AI 可见性度量 | **设计中** |
| 2 | 多模态以图搜图 | 买手上传样品图 → 匹配内部款式库与打样方案 | 待启动 |
| 3 | 企业微信引流 | 独立站访客 → 企微客户群 | 待启动 |

**顺序依据**：子项目 2 和 3 是流量转化与沉淀工具。没有子项目 1 产出的流量，做出来也是无源之水。

## 关键设计决策

| 决策 | 结论 |
|---|---|
| 交付物 | 内部 GEO 作战平台（Web 应用），**不是**给买手看的公司官网 |
| 租户模型 | 对内单租户，不对外提供 GEO 服务 |
| 底座 | GEOFlow（PHP 8.3 / Laravel / AGPL-3.0） |
| 许可证边界 | 内网使用；对公众只发静态产物，不暴露 GEOFlow 运行实例 |
| 业务信息 | 品类、能力点、目标问题全部**配置化**，不写死在代码里 |

## 二次开发的两个核心缺口

这两个缺口是「部署 + 录数据」之外真正需要写代码的地方：

1. **AI 可见性只支持国内引擎** —— GEOFlow 的采样提供商只有豆包 / DeepSeek，
   而目标市场在海外。不接入海外引擎，就没有验收标准。
2. **Organization Schema 只有一个名字** —— 需求要求「提供结构化设计资质与合规标准」，
   但当前生成的结构化数据缺 `sameAs` / `award` / `brand` / `hasCredential` 等字段，
   AI 无法据此把本公司在网络各处零散的信息归并为一个实体。
